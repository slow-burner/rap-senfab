# PRD — 계측 사전 지정 부하 모니터

| | |
|---|---|
| 문서 상태 | 초안 |
| 작성 | 2026-10-21 |
| 대상 독자 | 개발자, 계측 재공 담당, 기술 부서 팀장 |

---

## 1. 배경

반도체 팹의 계측 설비는 시스템이 자동으로 거는 기본 물량을 기준으로 CAPA 가
잡혀 있다. 이 물량은 예측 가능하고 CAPA 안에서 소화된다.

문제는 **기술 부서가 수동으로 추가하는 사전 지정**이다. 공정 변경점이 생기거나
설비 PM 이 끝나면 담당자가 "이 LOT 은 꼭 측정해 달라"고 계측 STEP 에 사전 지정을
건다. 정당한 요청이다. 그런데:

- 요청하는 쪽은 **자기가 거는 LOT 하나만 본다.** 계측 전체 부하는 안 보인다.
- 1매 측정 30분짜리 레시피를 6매 걸면 그 LOT 하나로 3시간이다. 거는 사람은 그걸 모른다.
- 계측 쪽은 **재공이 밀리고 나서야** 안다. 그때는 이미 측정이 돌아 되돌릴 수 없다.

지금은 이 상황을 사전에 볼 방법이 없다. Spotfire 로 보는 화면이 있으나 실적 확인용이고,
아직 측정하지 않은 대기 건의 예상 부하는 비어 있다.

## 2. 목표

### 2.1 1차 목표 — 사전 감지

**총측정시간이 임계치를 넘는 사전 지정 LOT 을, 측정이 돌기 전에 띄운다.**

```
총측정시간 = 1매 측정시간(PPID ST) × 사전 지정 매수    ← LOT 단위로 합산
```

LOT 단위 합산이 중요하다. 한 LOT 에 계측 STEP 을 여러 개 걸면 개별로는 임계 미만이어도
합치면 넘는다. 그게 실제 문제 사례다.

### 2.2 2차 목표 — 조정 요청

감지로 끝나면 아무것도 안 바뀐다. **요청 부서에 보낼 조정 요청 문안**을 만들어
그대로 복사해 보낼 수 있게 한다. 이것이 이 프로그램의 산출물이다.

### 2.3 3차 목표 — 누적 추적

한 번 넘긴 건 사정이 있었을 수 있다. 6주 연속 넘기면 관행이다. 주차별로 부서·PPID·
요청자를 누적해 그 차이를 보여준다.

### 2.4 비목표

- 사전 지정을 **자동으로 반려하거나 매수를 줄이는 것**. 권한 밖이고, 그렇게 하면
  기술 부서가 시스템을 우회한다. 이 프로그램은 알리는 데까지만 한다.
- 계측 스케줄링·디스패칭. 별도 시스템이 한다.
- 측정 결과(CD 값 등) 분석. SPC 시스템이 한다.
- 사전 지정 등록 화면. 기존 MES 화면을 쓴다.

## 3. 사용자

| 사용자 | 언제 보나 | 무엇을 하나 |
|---|---|---|
| **계측 재공 담당** (주 사용자) | 매일 아침, 교대 시 | 알람 확인 → 조정 요청 발송 |
| **기술 부서 담당** | 요청 회신 시 | 자기 요청이 왜 지목됐는지 확인 |
| **계측 팀장** | 주 1회 회의 | 주차별 추이로 부서 협의 안건 선정 |

## 4. 요구사항

### FR-1 알람 (최우선)

| ID | 요구사항 |
|---|---|
| FR-1.1 | LOT 의 사전 지정 총측정시간 **합**이 임계치 이상이면 알람에 포함한다 |
| FR-1.2 | 임계치는 화면에서 바로 바꿀 수 있다. 기본 120분 |
| FR-1.3 | 임계 × 2 이상은 '위험', 그 미만은 '주의' 로 구분한다 |
| FR-1.4 | 알람 배너는 **모든 화면 상단에 고정**한다. 어느 탭을 보든 보여야 한다 |
| FR-1.5 | 기본 모수는 **미진행(예정)** 이다. 이미 측정이 끝난 LOT 은 조정할 수 없다 |
| FR-1.6 | 배너에 위험·주의 건수, ST 합계, 최다 요청 부서·요청자를 함께 표시한다 |

### FR-2 조회

| ID | 요구사항 |
|---|---|
| FR-2.1 | 기본 조회 기간은 **최근 3일**, 최소 3일. 하루만 골라도 3일로 늘린다 |
| FR-2.2 | LINEID · EQP TYPE · 요청 부서 · 사유로 필터한다 |
| FR-2.3 | LOTID · PPID · STEP 으로 검색한다 |
| FR-2.4 | **STEP 단위와 LOT 단위를 전환**할 수 있다 (FR-1.1 의 합산 근거 확인용) |
| FR-2.5 | 조회 결과를 엑셀로 내려받는다 |

표에 나와야 하는 열: 요청일, LOTID, SLOT ID, EQP, **STEP SEQ**, STEP, PPID,
부서, 요청자, 1매당 측정시간, 매수, 총 측정시간, 사유, 승인상태, 상태.

### FR-3 조정 요청

| ID | 요구사항 |
|---|---|
| FR-3.1 | 부서별 조정 대상 LOT 을 집계한다 |
| FR-3.2 | 부서를 고르면 **복사용 요청 문안**을 만든다 |
| FR-3.3 | 문안에 대상 LOT, 총측정시간, 제안 매수, 절감 예상 시간을 포함한다 |
| FR-3.4 | 엑셀로도 내려받는다 |

### FR-4 주차별 현황

| ID | 요구사항 |
|---|---|
| FR-4.1 | **주차별 부서별 현황** — 부서 × 주차 행렬, 증감, 평균 상회 연속 주수 |
| FR-4.2 | **주차별 PPID·STEP SEQ Worst 10** — 전주 순위 대비 변동, 신규 표시 |
| FR-4.3 | **주차별 요청자 Worst 10** — 임계 초과 건수, STEP·PPID 드릴다운 |
| FR-4.4 | 기간 4 / 8 / 12주, 지표 측정시간 · LOT 수 · 매수 전환 |
| FR-4.5 | 세 화면이 **같은 모수**를 쓴다. 같은 주 합계가 일치해야 한다 |
| FR-4.6 | 진행 중인 주는 구분해 표시하고, 증감은 **끝난 주끼리만** 비교한다 |

FR-4.6 을 안 지키면 조회 끝일이 주 중간일 때 모든 부서가 '감소' 로 나온다.
증감 전체가 거짓말이 된다.

### FR-5 부하

| ID | 요구사항 |
|---|---|
| FR-5.1 | EQP TYPE 별 부하율 = 미진행 ST 합 ÷ 1일 여유 CAPA |
| FR-5.2 | 여유 CAPA = 설비대수 × 1440 × 가동률 − 기본유입_분 |
| FR-5.3 | CAPA 가 실측값이 아니면 화면에 **'예시값' 경고**를 표시한다 |

### FR-6 운영

| ID | 요구사항 |
|---|---|
| FR-6.1 | 사내 DB 없이 **샘플 데이터로 동작**한다 (개발·시연용) |
| FR-6.2 | 기준값·코드 매핑은 설정 파일 한 곳에 모은다 |
| FR-6.3 | DB 접속 정보는 저장소에 올리지 않는다 |
| FR-6.4 | 사내 웹 서버 상시 운영과 개인 PC 실행 파일, **같은 코드**로 둘 다 낸다 |

## 5. 성공 지표

| 지표 | 목표 | 측정 |
|---|---|---|
| 사전 감지율 | 임계 초과 LOT 중 **측정 전에** 발견한 비율 80% 이상 | 알람 시각 vs TKIN 시각 |
| 조정 회신율 | 발송한 요청 중 회신 비율 70% 이상 | 수기 집계 |
| 반복 초과 부서 | 3주 연속 평균 상회 부서 수 감소 | 주차별 화면 |
| 조회 응답 | 3일 조회 **5초 이내** | 운영 중 체감 |

지표가 안 나오면 화면을 더 만들 게 아니라 **조정 요청이 실제로 보내지고 있는지**부터 본다.

## 6. 가정

| 가정 | 틀렸을 때 |
|---|---|
| `AST_TIME` 은 1매 평균 측정시간이다 | 모든 시간 계산이 무의미해진다. **최우선 확인** |
| `AST_TIME` 의 단위는 분이다 | 60배 어긋난다. 설정 한 줄로 교정 가능 |
| `REQUEST_TYPE` 으로 Manual 을 구분할 수 있다 | 주차별 3화면이 전부 성립하지 않는다 |
| 사전 지정 슬롯은 쉼표 구분 문자열이다 | 매수 집계가 틀린다 |
| 한 LOT·STEP 의 계측 이력은 최근 1건만 보면 된다 | 재측정 LOT 에서 행이 불어난다 |

## 7. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 요청자 순위가 **인사 평가로 쓰인다** | 사전 지정을 안 걸고 구두로 부탁 → 데이터가 망가져 화면 자체가 무용 | 화면에 읽는 기준 명시. 팀장 합의 선행 |
| CAPA 예시값이 실값으로 보고된다 | 잘못된 의사결정 | 실측값 입력 전까지 화면에 경고 표시 |
| 파티션 키 미적용으로 팹 전체 스캔 | DB 부하, 조회 지연 | ERD 의 키 표를 따른다. 조회 시간 모니터 |
| 알람 피로 | 임계가 낮아 매일 수십 건 → 아무도 안 봄 | 운영 2주 후 임계 재조정 |

## 8. 범위 밖 (후보)

- 사전 지정 등록 시점에 예상 시간을 보여주는 MES 연동
- 임계 초과 시 메신저 자동 알림
- 측정 예정일 기반 날짜별 부하 분산 (현재는 조회 구간 전체를 1일 CAPA 와 비교)
- STEP_SEQ 채번 규칙 기반 "사전 지정까지 N스텝 남음"
