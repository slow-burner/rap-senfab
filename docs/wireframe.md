# WIREFRAME — 화면 설계

화면 14개의 구조. **무엇이 어디에 있는지**와 **왜 거기에 있는지**를 적는다.
글꼴·여백 같은 건 적지 않는다. 그건 CSS 에서 바뀐다.

```
기호   [버튼]  (▼선택)  [____입력]  ▣카드  ▤표  ▮▮그래프  ★고정
```

---

## 0. 공통 레이아웃

모든 화면이 같은 틀을 쓴다.

```
┌─ 사이드바 ────────┬─────────────────────────────────────────────────────┐
│                   │  계측 사전 지정 부하 모니터        2026-10-18 ~ 10-21 │
│ 데이터 조회 기간   │                                                     │
│ [2026-10-18 ~ 21] │ ┌─────────┬──────────────────┬──────────┬─────────┐ │
│ 최소 3일로 늘림    │ │전체 현황│부서별 Manual 현황│LOT 상세  │(▼기타)  │ │
│                   │ └─────────┴──────────────────┴──────────┴─────────┘ │
│ LINEID            │                                                     │
│ (▼전체)           │ ★━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━★ │
│ EQP TYPE          │ ★ ⚠ 위험 3건 · 주의 7건 · 예상 ST 24.5h            ★ │
│ (▼전체)           │ ★   최다 요청: 공정기술2팀 · 김○○                  ★ │
│                   │ ★   [조치 필요 목록 보기]                          ★ │
│ ─────────         │ ★━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━★ │
│ 요청 부서          │                                                     │
│ (▼전체)           │                                                     │
│ 사전 지정 사유     │            ← 선택된 화면 본문 →                      │
│ (▼전체)           │                                                     │
│                   │                                                     │
│ 총측정시간 알람    │                                                     │
│ 임계 (분)         │                                                     │
│ [    120    ]     │                                                     │
│ [x] 알람은        │                                                     │
│     미진행(예정)만│                                                     │
└───────────────────┴─────────────────────────────────────────────────────┘
```

### 왜 이렇게

| 요소 | 왜 거기에 |
|---|---|
| **알람 배너를 탭 위에 고정** | 1순위 요구사항. 어느 탭을 보든 보여야 한다. 탭 안에 넣으면 다른 탭에서 놓친다 |
| **임계치를 사이드바에** | 운영 2주 뒤 반드시 조정한다. 설정 파일을 고치러 가야 하면 아무도 안 바꾼다 |
| **'미진행만' 체크박스를 임계 바로 아래** | 기본 켬. 끄면 완료 건까지 알람에 들어온다. 과거 추세를 볼 때만 끈다 |
| **기간을 맨 위에** | 가장 자주 만지는 입력 |
| **부서·사유를 접어 둠** | 매번 쓰지 않는다. 기본 '전체' 로 두고 필요할 때 펼친다 |
| **탭 3개 + 나머지는 (▼)** | 14개를 가로로 늘어놓으면 줄바꿈되고 선택 상태가 안 보인다 |
| 제목 오른쪽에 조회 기간 | 캡처해서 보낼 때 "언제 기준" 이 같이 찍힌다 |

### 알람 배너 3단계

```
위험 있음  ━ 빨강 테두리 ━  ⚠ 위험 3건 · 주의 7건 · 예상 ST 24.5h
주의만     ━ 노랑 테두리 ━  ▲ 주의 7건 · 예상 ST 8.2h
없음       ─ 회색 ────────  임계 120분 초과 LOT 없음
```

"없음" 도 **반드시 표시한다.** 배너가 사라지면 사용자는 "문제 없음" 과
"조회가 안 됨" 을 구분할 수 없다.

배너의 모수는 **미진행(예정)** 이다. 이미 측정이 끝난 LOT 은 조정할 수 없으므로
알람을 띄울 의미가 없다.

## 1. 전체 현황 (기본 화면)

"지금 괜찮은가" 에 10초 안에 답하는 화면.

```
┌ KPI ────────────┬─────────────────┬─────────────────┬─────────────────┐
│ Manual 사전 지정 │ Manual 고부하   │ Manual 계측 예정 │ 고부하 PPID     │
│ LOT             │ PPID (120분↑)   │ 고부하 예상 ST   │ (전체 사유)     │
│                 │                 │                 │                 │
│    128 LOT      │     14 종       │    24.5 h       │     19 종       │
│ ▲ 12 직전 3일 대비│ ▲ 3 직전 3일   │ 여유 CAPA 대비  │ ▲ 5 직전 3일    │
│                 │                 │ 31.2% · ▲ 4.1h │                 │
└─────────────────┴─────────────────┴─────────────────┴─────────────────┘

▣ 사전 지정 추이 ─────────────────────────────────────────────────────────
│ ▮▮▮        ■ Manual   □ 기타                                          │
│ ▮▮▮  ▮▮    (일자별 누적 막대 + 임계 초과 건수 선)                      │
│ 10/18  10/19  10/20  10/21                                            │
└───────────────────────────────────────────────────────────────────────┘

▣ EQP TYPE × 사전 지정 사유 ──────────────────────────────────────────────
│ 상위 25% 칸을 진하게. EQP TYPE 을 고르면 STEP·PPID 단위로 바뀐다          │
│            Manual  PM AUTO QUAL  APC   DSM   합계                      │
│ METRCD      ████        ██        ▪     -    14.2h   ← 진한 칸 = 큼     │
│ OVL         ██         ███        ██    ▪     8.1h                     │
│ CDSEM       ▪           ▪        ████   ██    6.5h                     │
│                                                                        │
│ (EQP TYPE 을 고른 상태) → 행이 STEP·PPID 로 바뀜, Manual 상위 8개        │
│            Manual  PM AUTO QUAL  APC   DSM   합계                      │
│ MEA_CD (1420) · XYZ_30  ████      ▪     -     -     12.0h              │
└───────────────────────────────────────────────────────────────────────┘

▣ 조정이 필요한 LOT ──────────────────────────────────────────────────────
│ ▤ LOTID  STEP_SEQ  PPID   매수  총측정시간  부서      요청자  경과       │
│   AB12..   1420   XYZ_30   6     180분 ⚠   공정기술2  김○○   3일 ▮지연  │
│   CD34..   0880   PQR_25   5     125분      공정기술1  이○○   1일       │
│                                            [엑셀 다운로드]             │
└───────────────────────────────────────────────────────────────────────┘
```

### 왜

- **KPI 4개** — 2개면 판단이 안 되고 6개면 아무도 안 본다
- **전부 증감 표시** — 128 LOT 이 많은지 적은지 그 자체로는 모른다
- **KPI 2번 vs 4번** (Manual 고부하 / 전체 고부하) — 두 값이 벌어지는 폭이
  "Manual 이 얼마나 문제인가" 다. 같으면 Manual 탓이고 차이가 크면 기본 물량 문제다
- **KPI 3번에 CAPA 대비 %** — 분(分)만 보면 24.5h 가 큰지 모른다
- **추이는 2색** — Manual vs 기타. 사유 4종을 색으로 나누면 아무것도 안 읽힌다
- **행렬이 세 번째** — "어떤 설비에 · 어떤 사유로" 가 다음 질문이다. 사유를
  열로 둔 이유: 같은 설비 부하라도 Manual 이면 조정 요청이 되고 기본 물량이면
  CAPA 문제다. 조치가 다르다
- **EQP TYPE 을 고르면 행이 STEP·PPID 로 내려간다** — 설비까지 좁힌 다음 질문은
  "그 설비의 어느 작업이냐" 다. 화면을 옮기지 않고 한 단계 더 판다
- **'조정이 필요한 LOT' 이 맨 아래** — 여기서 바로 액션으로 간다. 모수는 미진행 중
  임계 초과 + 부하 주의·과부하 EQP 건. 경과 3일 이상은 빨강 (요청만 걸고 방치된 건)

## 2. 부서별 Manual 사전 지정 현황

"어디에 얘기해야 하나" 에 답한다.

```
┌ ▣ 부서별 ──────────────────┬ ▣ 요청자별 ──────────────────────────────┐
│ 공정기술2팀 ██████████ 12.4h│ 김○○  ████████████ 8.1h  ← 가로 막대   │
│ 공정기술1팀 ██████     7.2h │ 이○○  ████████     5.5h                │
│ 설비기술팀  ███        3.1h │ 박○○  █████        3.2h                │
│ (■ 임계 초과분  □ 임계 이하)│ 최○○  ███          2.0h                │
└────────────────────────────┴─────────────────────────────────────────┘

▣ Manual 요청 현황 ───────────────────────────────────────────────────────
│ STEP · PPID · 부서 · 요청자로 묶은 총측정시간 상위 12건                 │
│ ▤ STEP(SEQ) · PPID   부서       요청자  LOT수  매수  총측정시간         │
│   MEA_CD (1420) XYZ_30 공정기술2 김○○    6     36    18.0h             │
└───────────────────────────────────────────────────────────────────────┘

▣ 장시간 Manual LOT 분포 ─────────────── 기준 [  120  ]분 ───────────────┐
│ 기준 이상 LOT 만 · 행은 총측정시간 상위 10개 PPID                       │
│              10/18  10/19  10/20  10/21                                │
│ XYZ_30         ██     ███    ████    ██     ← 연속으로 진하면 관행      │
│ PQR_25         ▪      ██     ▪       ███                               │
└───────────────────────────────────────────────────────────────────────┘

▣ 일별 최대 총측정시간 STEP · PPID ───────────────────────────────────────
│ 그날 그 EQP TYPE 에서 STEP+PPID 별 총측정시간 합이 가장 큰 항목          │
│ ▤ 일자  EQP TYPE  STEP(SEQ) · PPID  LOT수  매수  총측정시간  주요 부서  │
│                                            [엑셀 다운로드]             │
└───────────────────────────────────────────────────────────────────────┘
```

### 왜

- **요청자 막대는 가로** — 세로로 하면 이름이 길어 x축 라벨이 비스듬히 눕고
  카드를 넘친다. 실제로 겪었다
- **막대 안에서 임계 초과분만 진하게** — 총량이 큰 부서와 초과가 많은 부서는
  다르다. 물량이 많아도 다 짧은 측정이면 문제가 아니다
- **히트맵의 기준 입력이 카드 안에** — 사이드바 임계와 별도로, 히트맵만 다른
  기준으로 보고 싶을 때가 있다
- **Manual 요청 현황을 STEP·PPID·부서·요청자로 묶음** — 조정 요청은 이 네 가지가
  다 있어야 보낼 수 있다. 하나라도 빠지면 "누구에게 무엇을" 이 안 정해진다
- **히트맵 행이 부서가 아니라 PPID** — 부서는 위 막대에서 이미 봤다. 여기서 볼 것은
  "같은 레시피가 며칠 연속 걸리고 있는가" 다. 그게 관행의 증거다
- **일별 최대 항목** — 평균은 튀는 날을 가린다. 날마다 '최악 하나' 를 보면 어느 날
  무엇 때문에 밀렸는지가 바로 나온다
- 요청자 이름은 화면에 띄우되 **순위를 인사 평가로 쓰면 안 된다.** 쓰면 사전
  지정을 안 걸고 구두로 부탁하게 되고, 데이터가 망가져 화면 자체가 무용해진다

## 3. LOT 상세 조회

"내 LOT 이 왜 지목됐나" 에 답한다. 기술 부서 담당이 쓰는 화면.

```
[__LOTID · PPID · STEP 검색__]   사유 (▼전체)   [ ] 장시간만 (120분↑)

보기 (전체|미진행|지연|승인 대기|완료|Cancel)  EQP TYPE (전체|METRCD|…)
단위 (STEP 단위 | LOT 단위)

조회 결과 342건 · LOT 128개 · 총측정시간 합 24.5h · 임계 초과 10건

▤ 요청일  LOTID  SLOT ID  EQP  STEP_SEQ  STEP  PPID  부서  요청자
         1매당  매수  총측정시간  사유  승인상태  상태
  10/21  AB12..  1,3,5,7,9,11  METRCD  1420  MEA_CD  XYZ_30  공정기술2  김○○
         30.0분   6     180분 ⚠   Manual  승인 완료  예정                  ▮지연
  ...
                                                    [엑셀 다운로드]

알람 = LOT 의 사전 지정 총측정시간 '합' 기준 (현재 임계 120분)
빨강 = 요청 후 3일 경과
```

### 왜

- **STEP / LOT 단위 전환이 핵심** — 알람은 LOT 합산인데 표는 STEP 단위다.
  합산 근거를 못 보면 사용자는 알람을 믿지 않는다. "우리 STEP 은 60분인데 왜
  알람이냐" 는 질문에 LOT 단위로 전환해서 보여주면 끝난다
- **'보기' 에 지연·승인 대기를 따로** — 상태가 아니라 동선이다. '지연' 은 요청만
  걸고 3일 넘게 안 움직인 건, '승인 대기' 는 아직 승인이 안 난 건. 둘은 조치가 다르다
- **'장시간만' 체크박스** — 임계 초과만 보는 가장 빠른 길. 사유·EQP 를 다 풀고도
  이것만 켜면 바로 대상이 나온다
- **SLOT ID 를 원문 그대로** — `1,3,5,7,9,11`. 매수(6)만 보여주면 어느 슬롯을
  뺄지 논의가 안 된다
- **1매당 시간을 따로 열로** — 총측정시간이 큰 이유가 "매수가 많아서" 인지
  "레시피가 비싸서" 인지 구분된다. 조치가 다르다
- **결과 건수를 표 위에** — 필터를 걸었는데 비면 "0건" 과 "조회 실패" 가 구분된다

## 4. 기타 분석 · 부하·CAPA

```
⚠ CAPA 는 예시값입니다. 실측값 입력 전까지 참고용입니다.     ← 실값 들어오면 사라짐

▣ EQP TYPE 별 일자 부하율 ────────────────────────────────────────────────
│ 미진행 사전 지정 기준 · ━ 100%  ┄ 80%                                   │
│ 120% ┤                      ╭─ CDSEM                                   │
│ 100% ┼━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                    │
│  80% ┼┄┄┄┄┄┄┄┄╭── METRCD ──╯                                           │
│   0% └──10/18────10/19────10/20────10/21──                             │
└───────────────────────────────────────────────────────────────────────┘
여유 CAPA = 설비대수 × 1440 × 가동률 − 기본유입

▣ PPID 별 부하 순위 ──────────────────────────────────────────────────────
│ 미진행 사전 지정 총측정시간 상위 15 · 해당 EQP 여유 CAPA 대비           │
│ XYZ_30 (METRCD)  ████████████  14.2h   여유 CAPA 대비 18.1%            │
│ PQR_25 (OVL)     ████████       9.1h   여유 CAPA 대비 11.5%            │
└───────────────────────────────────────────────────────────────────────┘
```

### 왜

- **경고 문구가 맨 위** — 예시값 부하율 83% 가 회의에서 실측값으로 보고되는
  사고를 막는다. `CAPA_IS_SAMPLE` 이 True 인 동안 계속 띄운다
- **부하율을 일자별 선으로** — 한 숫자로 "83%" 만 보면 그게 하루 몰린 건지
  고르게 깔린 건지 모른다. 하루만 튀는 거면 날짜를 옮겨 달라고 하면 끝난다
- **100% · 80% 기준선을 그래프에 그린다** — 선이 없으면 83% 가 괜찮은지 모른다
- **PPID 별 순위를 그 EQP 여유 CAPA 대비로** — 14.2h 가 큰지는 설비마다 다르다.
  설비 6대짜리의 14h 와 2대짜리의 14h 는 전혀 다른 얘기다
- **설비가 아니라 PPID 로 쪼갠다** — 부하율만 보면 "설비를 늘려야 한다" 로 끝난다.
  PPID 로 쪼개면 "이 레시피 물량을 조정하면 된다" 가 보인다

## 5. 기타 분석 · 부서별 조정 요청 ★ 실질 산출물

화면을 보는 게 목적이 아니라 **이 문안을 보내는 게 목적**이다.

```
▤ 부서별 조정 대상 ───────────────────────────────────────────────────────
```

### 왜

- **표가 아니라 문장** — 화면을 캡처해 보내면 받는 쪽이 뭘 해야 하는지 모른다
- **제안 매수와 절감 시간을 포함** — "줄여 달라" 와 "6매를 2매로 줄이면 2시간
  줍니다" 는 회신율이 다르다
- **첫 줄에 CAPA 초과 여부** — 왜 지금 조정이 필요한지의 근거. 여유가 있을 때는
  "여유는 있으나 확인 필요" 로 문구가 바뀐다. 과장하면 다음부터 안 읽는다
- **조회 기간을 문안에 박음** — 며칠 뒤 회신이 오면 어느 기준인지 모른다
- **"조정 또는 유지 사유를 회신" 으로 끝냄** — 조정을 강요하지 않는다. 유지해야 할
  이유가 있으면 그걸 받는다. 권한 밖의 일을 요구하면 다음부터 응답이 없다
- **코드 블록으로 출력** — Streamlit `st.code()` 는 오른쪽 위에 복사 버튼이 붙는다.
  메일·메신저에 그대로 붙인다. 이게 이 프로그램의 산출물이다
- **제안 매수는 `SUGGEST_SLOTS`(기본 2매)** — 설정값이다. 문안에 숫자를 박지 않는다

## 7. 주차별 부서별 현황

```
기간 (4주 | 8주 | 12주)    지표 (측정시간 | LOT 수 | 매수)    강조할 부서 (▼)

▤ 부서 × 주차 ────────────────────────────────────────────────────────────
│ 부서        8/25  9/01  9/08  ...  10/13  10/20*  증감    평균상회 연속  │
│ 공정기술2팀 10.1  11.2  12.0       14.1   6.2     ▲ 2.1h    6주 ⚠      │
│ 공정기술1팀  8.0   7.1   6.5        5.2   2.1     ▼ 1.3h    0주         │
│ 설비기술팀   3.1   3.0   3.4        3.2   1.5     ─         1주         │
│ ───────────────────────────────────────────────────────────────────    │
│ 전체 평균    7.1   7.1   7.3        7.5   3.3                          │
│                                     * 진행 중인 주 (증감 비교 제외)      │
└───────────────────────────────────────────────────────────────────────┘

▮▮ 선택 부서 추이 ─── ■ 선택 부서  □ 전체 평균 ───────────────────────────
```

### 왜 — 이 화면의 핵심 함정

**진행 중인 주를 증감 비교에 넣으면 안 된다.** 조회 끝일이 수요일이면 이번 주는
3일치다. 지난주(7일치)와 비교하면 **모든 부서가 '감소'** 로 나온다. 증감 전체가
거짓말이 된다. 실제로 겪었다.

→ 진행 중인 주는 `*` 와 흐린 색으로 표시하고, 증감은 **끝난 주끼리만** 비교한다.

- **"평균상회 연속 주수"** 가 이 화면의 결론이다. 한 주 많은 건 사정이 있다.
  6주 연속이면 관행이다. 부서 협의 자리에서 반박이 안 되는 숫자
- **지표 전환** — 측정시간이 큰 부서와 LOT 수가 많은 부서는 다르다. 조치가 다르다
- **전체 평균 행** — 비교 기준이 없으면 12.0h 가 많은지 모른다

## 8. 주차별 PPID·STEP SEQ Worst 10

```
기간 (4주 | 8주 | 12주)    지표 (▼)    주차 (▼2026-10-13주)

▤ Worst 10 ──────────────────────────────────────────────────────────────
│ #  STEP SEQ  STEP    PPID    EQP     1매ST  LOT  매수  측정시간  전주  변동│
│ 1    1420   MEA_CD  XYZ_30  METRCD  30.0분  18   108   14.2h   13.8h  ─  │
│ 2    0880   MEA_OV  PQR_25  OVL     25.0분  12    60    9.1h    4.2h  ▲3 │
│ 3    2100   MEA_TH  ABC_10  THK      8.0분  22    88    7.5h      -   NEW│
└───────────────────────────────────────────────────────────────────────┘
순위 변동은 전주 순위 대비. ▲ = 순위가 올라간 것(= 더 많이 걸었다)

추이를 볼 항목 (▼XYZ_30 / 1420)
▮▮ 선택 항목 12주 추이 ─────────────────────────────────────────────────
```

### 왜

- **PPID 와 STEP SEQ 를 한 묶음으로** — 같은 PPID 라도 STEP 이 다르면 다른
  작업이다. PPID 만으로 집계하면 조치할 대상이 안 좁혀진다
- **1매 ST · LOT · 매수를 같이** — 총측정시간이 큰 이유가 매수인지 레시피인지
  구분된다. 1매 8분인데 22랏 88매면 레시피가 아니라 물량 문제다
- **'전주' 열을 숫자로** — 순위 변동만 보면 1→2위가 급락인지 소폭인지 모른다
- **NEW 배지** — 이번 주에 새로 들어온 항목. 공정 변경점이 생겼다는 신호
- **▲ 의 의미를 캡션에 명시** — "순위 상승" 이 좋은 건지 나쁜 건지 모호하다.
  여기서는 **나쁜 것**이다

## 9. 주차별 요청자 Worst 10

```
기간 (4주 | 8주 | 12주)    지표 (▼)    주차 (▼2026-10-13주)

▤ Worst 10 ──────────────────────────────────────────────────────────────
│ #  요청자  부서        LOT  건수  매수  측정시간  전주   주평균  임계초과 │
│ 1  김○○  공정기술2팀   9    14    54    8.1h    7.6h   6.2h    4건    │
│ 2  이○○  공정기술1팀   7     9    38    5.5h    3.1h   4.0h    2건    │
└───────────────────────────────────────────────────────────────────────┘

STEP · PPID 별로 펼쳐 볼 요청자 (▼김○○)
▤ 김○○ · 2026-10-13주 ──────────────────────────────────────────────────
│ STEP SEQ  STEP    PPID     EQP     LOT  매수  총 ST(분)                 │
│   1420   MEA_CD  XYZ_30  METRCD    6    36     1,080                   │
└───────────────────────────────────────────────────────────────────────┘
```

### 왜

- **임계 초과 건수를 별도 열로** — 총량이 큰 사람과 과하게 거는 사람은 다르다.
  담당 제품이 많아 총량이 큰 건 문제가 아니다
- **'주평균' 열** — 이번 주만 많은 건지 늘 그런지. 주평균보다 이번 주가 크게 높으면
  일시적 이슈, 주평균 자체가 높으면 관행이다
- **드릴다운이 꼭 필요하다** — "김○○ 이 8.1h" 로는 대화가 안 된다.
  "1420 STEP 의 XYZ_30 에 6랏 36매" 까지 가야 조치가 된다
- **부서를 같이 표시** — 요청자 개인이 아니라 부서 단위로 협의한다

**이 화면은 인사 평가 자료가 아니다.** 화면에 그 기준을 명시한다. 평가로 쓰이면
사전 지정을 안 걸고 구두로 부탁하게 되고, 그 순간 데이터가 망가져 화면 전체가
무용해진다.

## 10~13. 보조 화면

| 화면 | 구조 | 왜 |
|---|---|---|
| **ST TOP 10** (총측정시간 TOP 10) | 기준 전환 `LOT·PPID·STEP·요청자·부서` → 상위 10 + Manual 비중 | 같은 데이터를 **보는 축만 바꾼다.** "어느 LOT 이냐" 와 "어느 부서냐" 는 다른 회의에서 쓴다. 화면을 5개 만들 이유가 없다 |
| **사유 분류** | 사유별 LOT·건수·매수·측정시간·비중 + 사유별 일자 추이 | Manual 비중이 추세로 늘고 있는지. 비중이 낮으면 이 프로그램 자체가 덜 필요하다 |
| **일자 추이** | 일자 × 부서 막대. **막대를 클릭하면** 그 날·부서의 LOT 목록이 아래에 뜬다 | "이 날 왜 튀었나" 를 화면을 옮기지 않고 본다 |
| **STEP 분포** | STEP SEQ · STEP 별 LOT·건수·총측정시간 | 특정 공정 구간에 몰려 있으면 그 구간 설비 CAPA 문제. 부서 조정으로 안 풀린다 |
| **전주 대비 PPID** | PPID 별 `직전 7일 ST` vs `최근 7일 ST` 증감 | 주차 화면보다 짧은 호흡. 갑자기 늘어난 PPID 를 주차 집계가 모이기 전에 본다 |

일자 추이의 클릭 드릴다운은 Plotly `on_select="rerun"` 으로 받는다.
선택이 없으면 "선택된 막대가 없습니다" 를 띄운다. 빈 공간을 두면 고장으로 보인다.

## 그래프 규칙 (전 화면 공통)

```
■ C1 #12a37a   Manual · 미진행 · 고부하 · 선택 강조
□ C2 #c9ecdd   그 외
▮ RED #c0392b  경고 전용 — KPI 증가 · 배지 · 지연 행. 그래프에는 쓰지 않는다
```

**색은 2가지만 쓴다.** 범주가 4개 이상이면 `Manual vs 기타`, `예정 vs 완료`,
`선택 vs 나머지` 중 하나로 묶는다. 색이 5개 있는 그래프는 아무 정보도 안 준다.
범례를 읽는 데 그래프를 읽는 시간보다 더 걸린다.

| 규칙 | 왜 |
|---|---|
| 항목 이름이 길면 **가로 막대** | 세로 막대는 x축 라벨이 눕고 카드를 넘친다 |
| 축 눈금 단위를 축 제목에 | 180 이 분인지 시간인지 모른다 |
| 비율 그래프는 축 범위 **0~100 고정** | 자동이면 60% 가 꽉 차 보인다 |
| facet 은 전 패널에 **같은 범위를 명시** | `matches="y"` 가 명시 범위를 덮어 100% 막대가 잘린다. 실제로 겪었다 |
| 데이터가 없으면 "데이터 없음" 표시 | 빈 캔버스는 고장으로 보인다 |

## 반응 · 상태

| 상황 | 화면 |
|---|---|
| 조회 중 | 스피너 + "조회 중" |
| 결과 0건 | "조건에 맞는 데이터가 없습니다" + 현재 필터 요약 |
| DB 접속 실패 | 빨강 박스 + 원인 + "샘플 모드로 전환" 안내. 백지로 두지 않는다 |
| CAPA 예시값 | 부하 화면 상단 노랑 경고 |
| 주차가 진행 중 | `*` 표시 + 흐린 색 + 증감 비교 제외 |

필터를 걸어 0건이 됐을 때 **현재 필터를 같이 보여주는 것**이 중요하다.
사용자는 자기가 어떤 필터를 걸었는지 금방 잊는다. "데이터가 없다" 만 뜨면
프로그램 고장으로 신고가 들어온다.
